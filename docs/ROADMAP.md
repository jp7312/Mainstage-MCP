# Integration roadmap

This alpha exposes a narrow performance-control surface. Each extension needs its own live evidence and explicit failure semantics before it becomes a supported capability.

- **Named actions:** the server now has a closed, capability-gated action vocabulary and transport-only press/release results. Metronome remains the only default action. Master mute and play/stop have narrow effect/reversal and port-isolation evidence; panic remains unverified, so CC85–87 stay one opt-in experimental group. Navigation candidates were removed after live no-op results. Never infer completion from a successful MIDI send.
- **Mapped parameters:** an opt-in single-slot CC90 probe now records sequenced screen-control callbacks with explicit 0–127 MIDI range, opaque display text and selection-scoped freshness. It remains experimental pending the bounded MainStage/IAC live recipe; do not equate callback feedback with complete plug-in parameter enumeration or acknowledgement.
- **Patch targeting:** explicit same-program/different-bank assignments passed in one disposable concert. This expands assignment control beyond 128 combinations but does not discover assignments or create durable patch identity. Callback list indices are not MIDI assignments, names can duplicate, bank is not reported, and the experimental global selector failed to address an orphan patch reliably. A durable selector still needs a verified host identity and isolated transport.
- **Isolated transport and installation:** complete driver discovery and MainStage acceptance tests before choosing a dedicated driver. The source prototype now passes a real CFPlugIn bundle-loader/ABI check without starting MIDI, but CoreMIDI discovery remains unproven; the next live gate requires a fresh login session, not another rescan. Require signing/distribution work, clean-machine installation/removal, and proof that existing MIDI identities and assignments survive before offering automatic setup. The current installer requires manually existing IAC buses.
- **Recovery and compatibility:** explicit helper reconnect now preserves an in-process endpoint-identity pin, invalidates held mutation context and never replays mutations; one live helper restart and synthetic crash, stale-callback and changed-route cases are covered. Still test MainStage quit/relaunch, unrelated MIDI topology notifications and sleep/wake. Multiple open concerts remain unsupported because the available session/name callbacks do not establish durable concert identity. Publish a tested macOS/MainStage/architecture matrix; a single successful local configuration is insufficient.
- **Broader editing:** arbitrary concert creation, plugin insertion, routing changes and full plugin editing require a separately verified host interface. MIDI control and MCP wrapping alone do not establish that interface.

See [validation](VALIDATION.md) for evidence already obtained and [setup](SETUP.md) for current operating limits.
